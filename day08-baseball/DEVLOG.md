# Day 08 · 숫자야구 — 개발 로그

`개발 예정`과 `개발 적용`을 한 파일에서 관리. 구현하면 예정에서 지우고 적용에 날짜와 함께 옮긴다.

---

## 개발 예정 (Planned)

- [ ] 효과음 (입력·스트라이크·아웃·승리)
- [ ] 자리수 5 이상 난이도 + 시간 제한 모드
- [ ] 추리 보조: 자리별로 확정/제외된 숫자를 표에 표시
- [ ] 결과 공유용 텍스트(시도별 S/B 요약) 복사
- [ ] 최적 추측 추천(후보를 가장 많이 줄이는 수) 표시

---

## 개발 적용 (Changelog)

### 2026-08-04 — 첫 버전 (v8.1)

- **기본 규칙**: 서로 다른 숫자로 된 정답, 자리+숫자 일치 = 스트라이크(S), 숫자만 일치 = 볼(B), 둘 다 없으면 아웃. 맨 앞자리 0 허용
- **난이도 2종**: 3자리(시도 10회) / 4자리(시도 12회). 헤드리스로 공정성 확인 — 단순 전략(남은 후보 첫 항목 추측)의 최악값이 3자리 9회·4자리 8회로 제한 안에 들어온다
- **입력**: 키패드 탭 + 물리 키보드(숫자/Enter/Backspace/Esc). 이미 쓴 숫자 키는 비활성, 자리수를 다 채우기 전엔 확인 버튼 비활성
- **시도 기록**: 최신이 위로 오는 목록에 숫자와 S/B 배지(스트라이크 초록·볼 파랑·아웃 회색) 표시
- **후보 수 표시(토글)**: 지금까지의 판정과 모순되지 않는 남은 정답 후보 개수. 기록에는 영향 없음
- **힌트(판당 1회)**: 한 자리의 숫자를 공개하고 슬롯에 점선으로 고정 표시. 쓰면 그 판은 최소 기록에서 제외
- **기록 저장**: 난이도별 **최소 시도 횟수**(적을수록 좋음)와 통산 판수·승수를 localStorage에 저장. 홈 카드에도 최소 시도를 노출
- 구조: 규칙·후보 추론·상태 머신을 DOM과 분리해 노드에서 그대로 테스트 가능하게 구성

#### 구현 중 잡은 것

- `new Game(...)` 생성 중에 `onChange`가 불려 아직 초기화되지 않은 `game` 상수를 참조하던 TDZ 오류 → 콜백이 인스턴스를 인자로 받게 수정
- `.stat { display: flex }`가 `[hidden]`을 덮어 후보 수 칸이 꺼져도 보이던 문제 → `.stat[hidden] { display: none }` 추가
