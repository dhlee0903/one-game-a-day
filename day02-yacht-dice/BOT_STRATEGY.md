# 야추 다이스 봇 전략

봇 AI의 설계·진단·개선 계획을 관리하는 문서.

---

## 1. 문제 진단 (2026-07-28)

시뮬레이션 평균은 ~178점이지만 실제 플레이에서 "멍청한" 홀드가 자주 보인다.
같은 입력을 여러 번 넣어본 결과(주사위 → 남긴 주사위):

| 상황 | 기대 | 실제 (반복) |
| --- | --- | --- |
| `[1,2,3,4,6]` (4-스트레이트) | `1234` 유지 | `_234_`, `____6`(6만!), `__34_`, `___46` — 제각각 |
| `[2,2,4,4,5]` (투페어→풀하우스) | `2244` 유지 | `____5`(5만!), `_24_5`, `2_4__` — 제각각 |
| `[6,6,6,6,2]` (4-of-a-kind) | `6666` 유지 | `6666_` ✅ |

**원인**: 홀드를 **몬테카를로 40 샘플 + 2-롤 휴리스틱(quickKeep)**으로 평가 →
- **분산이 커서** 같은 입력에 매번 다른 결정 (특히 여러 후보의 기대값이 비슷할 때)
- 스트레이트·투페어처럼 "확률로 완성되는" 손의 잠재가치를 저평가/불안정 평가

## 2. 목표

- 홀드 결정이 **결정론적이고 턴 단위 최적(myopic-optimal)**
- 스트레이트·풀하우스·야추 등 **잠재가치를 정확한 확률**로 평가
- 결정당 **< 50ms** (봇 연출 페이싱에 영향 없음)
- 시뮬 평균 **200+ 목표** (현 178)

## 3. 알고리즘 — 턴 단위 정확 기대값 (Exact EV)

몬테카를로를 버리고 **정확 확률 DP**로 교체.

- 상태를 **정렬된 주사위 멀티셋**으로 축약 → 고유 상태 252개뿐, **메모이제이션**으로 재사용
- 리롤 분포: j개 주사위를 굴렸을 때 나오는 멀티셋과 그 확률을 **미리 계산**(정적)

```
value(dice, r):                      # r번 리롤 남았을 때 최적 플레이의 기대 배치가치
  if r == 0: return bestPlacement(dice)
  return max over keep-subset K of:
           E over reroll( value(K + reroll, r-1) )   # 리롤 분포로 정확 기대값
```

- keep-all(전부 유지)도 후보에 포함 → 그게 최적이면 자연히 스탠드(리롤 안 함)
- `chooseHolds`는 실제 5개 주사위의 32개 keep-mask 중 `value` 최대를 고름
- 메모는 (열린 카테고리 + 상단 합)이 바뀔 때만 초기화 → 한 턴 내 재사용

## 4. 배치 가치 — 홀드와 카테고리 선택을 통일

```
desirability(id, dice) = score(id) - PAR[id]
                         + (상단이면) 보너스 추구/63 확보 보정
bestPlacement(dice)    = max over 열린 카테고리 of desirability
chooseCategory(dice)   = argmax over 열린 카테고리 of desirability
```

- **PAR**(카테고리별 기대값) 대비 초과분으로 평가 → 큰 조합 슬롯(야추·스트레이트)은
  큰 손일 때만 채우고, 버림은 par가 낮은 곳으로 → 슬롯 낭비 방지
- 홀드(`bestPlacement`)와 최종 선택(`chooseCategory`)이 **같은 가치함수**를 써서 일관됨

## 5. 검증 계획

- **시나리오(결정론적)**: 4-스트레이트 유지, 투페어 유지, 4-of-a-kind 유지, 야추는 야추 칸으로
- **강도**: 솔로 시뮬 평균 (목표 200+), Yacht 성공률
- **성능**: 결정당 ms 측정

## 개발 적용 (Changelog)

### 2026-07-28 — 몬테카를로 → 정확 EV DP

- 홀드를 **정확 기대값 DP**로 교체 (정렬 주사위 멀티셋 메모이제이션 + 리롤 정확 분포)
- 결과: **결정론적**이고 정상적인 홀드
  - `[1,2,3,4,6]` → `1234` 유지(스트레이트 추격) ✅
  - `[6,6,6,6,2]` → `6666` ✅, `[5,5,5,3,2]` → `555` ✅
  - 이전의 "6만 남김 / 5만 남김" 같은 노이즈 제거
- 성능: 결정당 ~110ms (턴당 1회, 봇 페이싱 안이라 무감)
- 강도: 솔로 시뮬 평균 ~175 (기존과 비슷), **최고 290 → 326**

### 남은 과제

- 평균 상향은 **턴 단위(myopic)** 한계 → 게임 전체 상태 DP(카테고리 조합 × 상단 점수)로
  기대값을 풀면 더 강해짐. 큰 작업이라 후속 과제로 둠.
- PAR(카테고리 기대값) 정밀 튜닝으로 소폭 개선 여지.
